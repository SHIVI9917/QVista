# Regenerating the screenshots

Every image in `../images/` that shows the interface is produced by one
of these two scripts. They live here so the figures can be regenerated
whenever the interface changes, rather than drifting away from it.

Run them from the repository root, with QVista's virtual environment
active:

```bash
cd /path/to/QVista
source .venv/bin/activate                  # Windows: .venv\Scripts\activate

python docs/tutorial/tools/capture_dialogs.py
python docs/tutorial/tools/capture_window.py
```

Both write straight into `../images/`, overwriting what is there. They
take an optional argument: the structure file to load, defaulting to
`LiMnO2-1819592.vasp` in the current directory, which is the demo
structure shipped with QVista and the one every page refers to.

| Script | Produces |
|---|---|
| `capture_dialogs.py` | the 32 dialog screenshots |
| `capture_window.py` | the 9 main-window screenshots, `01-` to `09-` |

## Two things that are easy to get wrong

**Build the application with `create_application()`, never a bare
`QApplication`.** That call is what applies QVista's theme stylesheet.
Skipping it gives unstyled native Qt widgets — which is not what anyone
running QVista sees, and on the INCAR and KPOINTS dialogs it renders the
field labels white on white. The first generation of these screenshots
was made that way and had to be redone.

**The 3D viewport will not appear in `QWidget.grab()`.** VTK draws
through a native OpenGL surface that never enters Qt's backing store, so
the viewport comes back solid black. `capture_window.py` renders it
separately through VTK's own screenshot and paints it into the grab.
Compositing is deliberate: grabbing the screen instead would depend on
the window being frontmost and could capture whatever else happens to be
on the desktop.

The dialog script runs under Qt's offscreen platform, so it needs no
display and puts no windows on screen. That platform starts with an
empty font database on Windows, which is why the script registers font
files by path before drawing anything. The window script cannot use
offscreen, because VTK gets no OpenGL context there.

## The plots

`result-*.png` are not screenshots. They are figures from real
calculations — a real `DOSCAR`, a real 14 ps VASP AIMD run at 1600 K —
exported from QVista and not regenerated by these scripts.
